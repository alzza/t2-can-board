# 채팅 로그 - 2026-08-05~06 실차 로그

## 사용자 요청

- 최신 실차 로그 기준으로 추가 안정화가 필요한지 판단한다.
- Web UI에서 3회로 보인 값과 BUS-OFF 전용 이력이 비어 있는 이유를 확인한다.
- S3 디스플레이 정상 동작을 확인했다.

## 분석 결론

- 이번 자료에는 B채널 BUS-OFF가 없다. 사용자가 본 3은 `BUS-ERR` 누적이며 BUS-OFF와 다른 지표다.
- B채널은 두 20분 구간 전체에서 RUNNING, TEC/REC=0, TX Fail=0이었다.
- CAN 송신·복구 로직을 다시 크게 바꿀 근거는 없으며 현재 펌웨어를 기준선으로 유지하는 편이 타당하다.
- 남은 개선 대상은 기능 알고리즘보다 관측성이다. BUS-ERR를 `BUS-OFF 아님`으로 명확히 표시하고, 실제 BUS-OFF가 발생할 때 카운터·복구·전용 이력의 정합성을 자동 검사하는 회귀 테스트가 필요하다.
- A채널에는 14시간 22분 동안 RX 오버런 5회와 TX_FAIL Guard 27회가 남아 있으나 큐 드롭·BUS-OFF·TEC/REC 상승은 없다. 즉시 구조 변경보다는 다음 실차 로그에서 증가율을 계속 확인한다.

## 사용자 승인 후 적용

- `BUS-OFF 0 / BUS-ERR 3`을 같은 영역에서 비교하고 BUS-ERR가 BUS-OFF가 아님을 설명하도록 Web UI를 수정했다.
- 실제 BUS-OFF의 복구 결과가 전용 이력에 정확히 한 행만 저장되는 기록기를 적용하고 성공·실패·중복 완료 회귀 테스트를 추가했다.
- CAN 송신·복구 조건과 드라이버 호출 순서는 변경하지 않았다.
- 전체 native 107건과 실제 HW3 빌드가 통과했으며 날짜 규칙의 OTA BIN을 생성했다.
