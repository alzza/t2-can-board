# 채팅 로그 요약

## 사용자 요청

- 통합 CanMod 로그를 제외한 CSV 저장 결과가 이상하므로 저장 루틴을 다시 작성한다.
- 각종 플래그, 발생 시각, 이벤트, 채널별 정보를 저장한다.
- 실차 주행 중 문제 원인을 분석하고 CSV 정보도 개선한다.
- A채널 경고·에러 원인을 파악해 통신 문제가 재발하지 않도록 수정한다.
- 진단 UI, Web 로그, Serial 단순화 방안 중 `1-A / 2-A / 3-A`를 적용한다.

## 확인한 사실

- CSV 행의 쉼표 개수 자체는 깨지지 않았다.
- 문제는 시간 기준 불일치, 채널 부재, 메타행 혼재, 빈 자가 진단, 이벤트 보존 부족, 수동 기록 정지 의미 불일치였다.
- 실차 A채널 경고는 EFLG `0x80/0xC0` RX 오버런이다.
- A TEC/REC/MERRF와 BUS-OFF 증거가 없어 물리 CAN 오류로 단정하지 않는다.
- B 중재 실패는 TEC/REC·Bus Error·TX Fail이 0인 조건에서는 버스 우선권 양보다.

## 적용 원칙

- 검증된 INO 기반 HW3 Summon Unlock과 TSLLC 프레임 수정 로직은 변경하지 않는다.
- A One-Shot과 TX Guard를 끄는 방식으로 경고를 숨기지 않는다.
- 원인인 A 폴링 공백과 반복 이벤트 보존을 직접 개선하고 계측한다.
- 실차에서 0회 재발을 아직 확인하지 않았으므로 코드 검증 완료와 실차 검증 완료를 구분한다.
- 진단은 요약 카드 우선, 상세 카운터는 기본 접힘으로 둔다.
- Web 로그는 중요 항목 기본 표시, Serial은 중대 상태 전환만 출력한다.
- 표시만 존재하고 실제 출력에 영향을 주지 않던 `Enable Log` 플래그는 제거한다.

## 검증 결과

- Native 전체 100개, Nag 전용 23개 테스트 통과.
- HW3 `lilygo_t2can` 빌드 성공.
- 검증된 Summon bit46/bit19, ID 659 제거, Nag MODE 1/2/3, OTA TX 차단 회귀 테스트 유지.
- 브라우저 연결 환경이 없어 실제 클릭 검증은 제외했으며 HTML5/JavaScript 정적 검사와 Web UI 회귀 테스트로 확인.
