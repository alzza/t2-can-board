## 저장 문제

- `can_diag.csv`는 14바이트이며 `t_ms,message` 헤더 한 줄만 있다. 자가 진단을 실행하지 않은 상태에서 저장한 파일이다.

- `events 3.csv`는 200행, 7열이지만 최초~최종 이벤트 범위가 363초뿐이다.
- 이벤트 200행은 `A_EFLG_SET 51`, `A_EFLG_CLEAR 51`, `A_RX_OVERRUN 98`로 모두 A채널 오버런 관련 이벤트다. 반복 이벤트가 링버퍼를 채워 B채널과 이전 사건을 밀어냈다.
- 시계열은 `t_s`, 이벤트는 `t_ms`, 통합 로그는 실제 날짜·시간을 사용해 같은 사건을 바로 대조하기 어렵다.
- CSV의 `#` 메타행은 본문과 열 수가 달라 일반 표 프로그램에서 하나의 정상 테이블로 인식하기 어렵다.
- 기존 수동 기록은 정지 후에도 백그라운드 샘플을 계속 추가해 사용자가 고정하려던 구간을 바꿨다.

## 실차 통신 분석

### A채널

20분 시계열 변화량:

- 수신 프레임 `+133,839`
- TX 성공 `+1,778`, TX 실패 `+37`
- RX 오버런 `+360`
- EFLG 진입 `+196`
- MERRF 변화 `0`
- TEC/REC 현재·피크 `0`
- BUS-OFF `0`

EFLG는 `0x80` 또는 피크 `0xC0`이며 RX1OVR/RX0OVR이다. TEC/REC와 MERRF가 0이므로 배선·종단저항·ACK 오류보다 MCP2515의 2개 RX 버퍼를 제때 비우지 못한 소프트웨어 폴링 공백이 원인으로 판단된다.

### B채널

20분 시계열 변화량:

- 중재 실패 `+10,730`
- Echo `+11,040`
- Bus Error 변화 `0`
- TX Fail `0`
- TEC/REC `0`
- BUS-OFF `0`

중재 실패와 Echo 증가량이 비슷하고 오류 카운터가 0이므로, 다른 프레임에 버스 우선권을 양보한 기록이다. 이것만으로 물리 CAN 오류로 판정하지 않는다.

## 적용 결과

- 개별 CSV는 UTF-8 BOM과 단일 헤더를 사용하는 순수 CSV v2가 됐다.
- 모든 시계열 행은 `wall_time`과 `uptime_ms`를 함께 가진다.
- 시계열 컬럼은 `a_`, `b_`, `system_` 접두사로 채널·범위를 구분한다.
- 이벤트는 최초/최종 실제 시각, 업타임, 채널, 심각도, 발생 횟수, TEC/REC, 원시 detail, 해석 text를 저장한다.
- A 오버런과 B 반복 alert는 30초 동안 묶고 최초/최종 시각과 횟수를 보존한다.
- 자가 진단을 실행하지 않았으면 빈 파일 대신 `NOT_RUN` 안내 행을 저장한다.
- 수동 기록 정지 시 시계열을 고정하며 기본 상태에서는 자동 최근 20분 버퍼를 유지한다.
- 기능 토글, 기록 시작/정지/초기화, A TX Guard 진입/해제, SPI 목표 변경, B BUS-OFF/복구를 이벤트로 남긴다.
- A채널 폴링의 최근/최대 공백과 2ms 초과 횟수를 기록한다.
- Core 1의 주기 USB 시리얼 출력을 제거하고 Web 로그링은 유지한다.
- B RX burst 8프레임마다, 그리고 1ms 태스크 양보 직전에 A MCP2515를 다시 비운다.
- 진단 화면은 A/B 요약을 항상 보여주고 상세 카운터와 BUS-OFF 표는 기본 접힘으로 표시한다.
- Web 실시간 로그는 중요 항목을 기본 표시하고 전체 로그는 선택 시 표시한다. 다운로드 원본은 필터링하지 않는다.
- Serial은 부팅·OTA·초기화 실패·BUS-OFF/복구·TEC/REC 임계값 전환만 남긴다.
- 실제 코드 출력 경로에서 사용되지 않던 `Enable Log`, `enable_print`, `/api/enable-print`를 제거했다.

## 실차 재검증 판정

새 펌웨어로 최소 20분 주행 후 다음을 본다.

1. `a_d_rx_overrun` 합계가 0이거나 기존 360회보다 크게 감소해야 한다.
2. `A_RX_OVERRUN` 이벤트가 있으면 `detail_text`의 `loop_gap_us`가 2,000us 이상인지 확인한다.
3. 같은 구간 `a_d_loop_gap_over_2ms`와 오버런 증가가 함께 나타나는지 확인한다.
4. TEC/REC/MERRF가 0인데 오버런만 남으면 폴링·버스트 문제로 계속 본다.
5. TEC/REC 또는 MERRF가 함께 증가하면 그때부터 배선·종단·ACK 문제를 별도로 조사한다.
