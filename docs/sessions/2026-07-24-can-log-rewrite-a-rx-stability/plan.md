# 작업 계획

## 목표

- 실차 로그 파일별 시간·채널·플래그 의미가 일치하도록 CSV 저장 구조를 다시 작성한다.
- 헤더만 저장된 자가 진단 CSV, 이벤트 덮어쓰기, 수동 기록 정지 후 데이터가 계속 바뀌는 문제를 해결한다.
- A채널 간헐 경고의 실제 원인을 확인하고 검증된 HW3 Summon/TSLLC 송신 규칙을 바꾸지 않는 범위에서 RX 오버런을 줄인다.

## 진행 순서

1. `can_diag.csv`, `events 3.csv`, `timeseries 3.csv`, 통합 로그를 같은 운행 구간 기준으로 대조한다.
2. 각 CSV의 열 개수, 시간 기준, 보존 구간, 채널·플래그 정보를 확인한다.
3. 이벤트 레코드를 채널·심각도·최초/최종 시각·반복 횟수 구조로 개편한다.
4. 시계열 CSV를 순수 CSV 형식과 채널 접두사 컬럼으로 개편한다.
5. 수동 기록 정지 시 버퍼를 고정한다.
6. A/B 통합 태스크의 장시간 작업과 시리얼 출력을 줄이고 B burst 중 A채널을 재서비스한다.
7. A 폴링 공백을 API, UI, 시계열, 오버런 이벤트, 자가 진단에 추가한다.
8. Native 테스트, Nag 테스트, Web UI 동기화, printf 검사, HW3 보드 빌드를 실행한다.
9. 확정안 `1-A/2-A/3-A`에 따라 진단 요약 우선 UI, 중요 Web 로그, 최소 Serial 정책을 적용한다.

## 변경하지 않는 항목

- HW3 Summon Unlock의 ID 1021 mux 1, bit19=0, bit46=1 규칙.
- INO 기준 `Parked || Summoning` 게이트.
- TSLLC의 검증된 mux 0 수정 규칙.
- Nag MODE 1/2/3 프레임 생성 규칙과 안전 상한.
- A MCP2515 One-Shot과 A TX Guard 기본 ON 정책.
