## 3. loop() vTaskDelete(NULL) 적용 — ✅ 완료

### 변경 내용

**파일**: `src/main.cpp`

```cpp
// 변경 전
void loop() {
    // A/B 채널 폴링은 모두 nagKillerTask(Core 1)에서 통합 처리.
    // Arduino loopTask(Core 1, prio 1)는 IDLE 양보용으로만 유지.

    if (gOtaRecoveryModeActive) {
        vTaskDelay(pdMS_TO_TICKS(100));
        return;
    }
#endif
    vTaskDelay(pdMS_TO_TICKS(100));
}

// 변경 후
void loop() {
    // 모든 작업은 RTOS 태스크에서 처리. loopTask 즉시 삭제.
```

### 검토 근거

- `vTaskDelete(NULL)` — Arduino-ESP32 2.0.17 공식 지원 패턴
- loopTask 삭제 후 Core 1에는 `nagKillerTask(prio 10)`만 남아 실행

## 4. MCP2515 SPI 기본값 8MHz → 10MHz 변경 — ✅ 완료

### 사용자 요청
> "나도 통신속도를 10MHz로 기본으로 설정해야할까? 가능하다면 펌웨어 디폴트 값을 10MHz로 변경해줄래?"

### 근거
- MCP2515 데이터시트 최대 정격: **10MHz**
- Saturn 프로젝트: `CanBusMcp2515(10, 9, &SPI)` — 10MHz 하드코딩 사용 중
- T2-CAN 보드는 MCP2515 전용 설계 → 10MHz 완전 지원
- Web UI에서 8/10MHz 토글 여전히 가능 (안전한 폴백 수단 유지)

### 변경 파일 및 내용

**1) `platformio.ini`**
```ini
# 변경 전
-D T2CAN_SPI_FREQ_HZ=8000000 ; [A실험 기본] 웹 UI에서 8/10MHz 선택 가능

# 변경 후
-D T2CAN_SPI_FREQ_HZ=10000000 ; [A기본] MCP2515 최대 정격. 웹 UI에서 8/10MHz 선택 가능
```

**2) `include/t2can_pins.h`** (fallback)
```cpp
// 변경 전
#define T2CAN_SPI_FREQ_HZ 8000000

// 변경 후
#define T2CAN_SPI_FREQ_HZ 10000000
```

**3) `include/can_helpers.h`** (fallback)
```cpp
// 변경 전
#define T2CAN_SPI_FREQ_HZ 8000000

// 변경 후
#define T2CAN_SPI_FREQ_HZ 10000000
```

### 코드 자동 반영 항목
- `kAMcpDefaultSpiFreqHz = T2CAN_SPI_FREQ_HZ` → 10MHz 반영
- `web_server.h` NVS 로드 시 `defaultMhz = (kAMcpDefaultSpiFreqHz >= 10000000) ? 10 : 8` → 10으로 분기
- Web UI 토글 `a_spi_8mhz` → 기본 OFF 상태 (10MHz) 표시

## 6. NVS 최초 1회 초기화 구현

### 목적
펌웨어 최초 플래시 후 잔재 NVS 키가 동작에 영향을 주는 것을 방지.

### 배치 위치
`otaBootCheck()` 직전 → OTA 키(`ota_pending`, `ota_fallback`)가 초기화 이후에 설정되므로 덮어쓰기 방지.

### 구현 (`src/main.cpp`)
```cpp
{
    nvs_handle_t initHandle;
    if (nvs_open(kNvsNamespace, NVS_READWRITE, &initHandle) == ESP_OK) {
        uint8_t initDone = 0;
        if (nvs_get_u8(initHandle, "nvs_init_ok", &initDone) == ESP_ERR_NVS_NOT_FOUND) {
            nvs_erase_all(initHandle);
            nvs_set_u8(initHandle, "nvs_init_ok", 1);
            nvs_commit(initHandle);
            Serial.println("[NVS] 최초 부팅: NVS 초기화 완료");
        }
        nvs_close(initHandle);
    }
}
otaBootCheck();
```

### 멱등성
`nvs_init_ok` 키 존재 여부로 판단 — 이후 부팅에서는 재실행 없음.

### 현장 주의사항
기존 장치에서 펌웨어 업데이트 시 NVS 전체 초기화 → 모든 설정(SPI 속도, 토글 등)이 기본값으로 리셋됨.

## 13. CAN 초기화 / BUS-OFF 대책 재정비

### 사용자 요청
> "너의 추천 판단대로 모두 수정해달라 마지막 10mhz 까지 ..전부다."

### 반영 내용

1. **B채널 TWAI 복구 경로 정리**
    - ESP-IDF v4.4 상태 머신 기준으로 BUS-OFF 시 `twai_initiate_recovery()`를 먼저 사용하도록 변경.
    - Recovering 완료 후 Stopped 상태에서 `twai_start()`로 재개.
    - soft recovery 실패 또는 드라이버 상태 이상 시에만 hard reinstall fallback 수행.
    - BUS-OFF 상태에서 무조건 `twai_stop()`을 호출하던 경로 제거.

2. **A채널 MCP2515 TXBO 복구 추가**
    - `CanDriver` 공통 bus-off recovery hook 추가.
    - `MCP2515Driver`가 reset pin을 받아 하드웨어 reset/reinit 복구를 수행할 수 있게 변경.
    - `appLoop()`의 기존 EFLG/TXBO 진단 루프 안에 throttled recovery window를 연결.
    - TXBO가 오래 지속될 경우 최종 fallback까지 갈 수 있도록 Saturn식 recovery window 패턴 반영.

3. **진단/웹 상태 노출 보강**

## (세션 연속) 아키텍처 박스 갱신 + NVS init 버그 수정

### 사용자 요청
> "현재 아키텍처 갱신해줄래? 또 OTA최초 업로드시 nvs삭제하는거 아직도 유효한지 또는 버그가 없는지 검토해봐. 지금 꼬인거같은데."

### 분석 결과

#### NVS init 버그 (실제 발견)
기존 코드는 `nvs_init_ok`가 없을 때 **무조건 `nvs_erase_all()` 수행**했다.

| 시나리오 | `ota_pending` | 기존 동작 | 문제 |
|---|---|---|---|
| 최초 시리얼 플래시 | 0 | erase_all → init_ok | ✅ 정상 |
| 구버전 FW에서 OTA 업그레이드 | 1 (설정됨) | erase_all → OTA 키만 복원 | ❌ 사용자 설정 전체 소멸 |

**핵심**: `nvs_init_ok`가 없는 구버전 FW에서 OTA 업그레이드 시 → `ota_pending=1` 상태인데 `nvs_erase_all()`이 돌면서 사용자 설정(SPI 속도, 토글 상태 등)이 전부 날아감. 코드는 OTA 키만 복원했지만 다른 모든 설정은 손실.

#### 아키텍처 박스 (구버전)
- B채널 BUS-OFF 설명: `hard re-install + 쿨다운` (이전 세션에서 soft→hard fallback으로 변경됐지만 박스 갱신 안 됨)
- A채널: TXBO recovery hook 누락

### 수정 내용 (`src/main.cpp`)

**1. NVS init 블록 버그 수정**

```cpp
// 수정 전 (버그 있음)
nvs_erase_all(initHandle);  // 무조건 erase
nvs_set_u8(initHandle, "nvs_init_ok", 1);
if (otaPending != 0) {
    nvs_set_u8(initHandle, kNvsKeyOtaPending, otaPending);
    nvs_set_str(initHandle, kNvsKeyOtaFallback, otaFallback);
}  // 다른 설정은 복원 안 됨!

// 수정 후 (버그 수정)
uint8_t otaPending = 0;
nvs_get_u8(initHandle, kNvsKeyOtaPending, &otaPending);
if (otaPending == 0) {
    nvs_erase_all(initHandle);  // 최초 시리얼 플래시만 erase
    Serial.println("[NVS] 최초 시리얼 플래시: NVS 초기화 완료");
} else {
    // OTA 업그레이드: 기존 설정 전체 보존, init_ok만 추가
    Serial.printf("[NVS] OTA 업그레이드 감지(pending=%u) — 설정 보존\n", otaPending);
}
nvs_set_u8(initHandle, "nvs_init_ok", 1);
nvs_commit(initHandle);
```

추가: `nvs_flash_init()` 호출을 init 블록 내부로 이동 (idempotent, otaBootCheck() 호출 전 NVS 보장).

**2. 아키텍처 박스 갱신**
- A채널: `EFLG/TEC/REC/MERRF 1초 주기 폴링` → `EFLG/TEC/REC/MERRF 1초 주기 폴링 + TXBO recovery hook`
