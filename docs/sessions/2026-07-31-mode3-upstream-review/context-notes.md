# 2026-07-31 Mode 3 상류 재검토 컨텍스트 노트

## 상류 기준

- 확인 기준은 `ev-open-can-tools` dev 커밋
  `e54d3a7b202e5f4e624df067d0103575475a14f7`이다.
- 3.0.2-beta.13은 AP 송신 게이트가 닫혀 있어도 Mode C가 DAS와 조향
  컨텍스트를 계속 갱신하되, 모든 공통 게이트가 열리기 전에는 송신하지 않도록
  수정했다.
- 상태와 지원 진단의 AP 게이트 권한·차단 사유·AP 활동·안정시간·주차·소환
  보고는 CSV 레코더가 아니라 `/status` JSON과 요청 시 생성하는 텍스트 지원
  보고서다.
- 상류가 CSV를 뜻할 때는 변경 이력에 recorder/CSV라고 별도로 명시한다.

## HW3 Mode C 조건

- 대상 프레임은 EPAS `0x370(880)`, HW3 DAS `0x399(921)`, 조향
  `0x129(297)`이다.
- AP 상태는 DAS byte 0의 하위 4비트, hands-on 상태는 byte 5 bit 2~5,
  조향각은 `0x129` byte 2~3과 -819.2도 오프셋을 사용한다.
- DAS와 조향은 각각 최근 1초 이내, AP 상태 3~6, 조향 validity=1,
  조향각 ±5도 안에서만 허용한다.
- hands-on 상태 2는 진입 2초 뒤 ±0.5~1.8Nm 임의 보행을, 상태 3은 진입
  1초 뒤 -1.8~+1.8Nm 삼각파를 사용한다.
- 상류는 HW4의 실차 제어 오류 때문에 모든 Nag 모드를 차단했지만,
  HW3 알고리즘·ID·프레임·체크섬·토크 제한은 변경하지 않았다고 명시한다.

## 현재 프로젝트와의 핵심 차이

- 현재 프로젝트의 과거 실차 로그는 `921=0`이고 `923(0x39B)`가 실제 DAS
  소스로 반복 확인됐다.
- 상류 HW3 Mode C를 그대로 이식하면 `0x399`를 기다리며 fail-closed 상태로
  송신하지 않을 가능성이 높다.
- 따라서 Mode 3 재이식은 실험 기능으로는 조건부 권장하지만 기본 활성화는
  비권장한다. 먼저 같은 주행 구간의 921/923 원시 8바이트와 AP 상태 해석을
  비교해 입력 ID와 레이아웃을 확정해야 한다.
- 확인 전에는 기존에 삭제한 Mode 3 알고리즘과 NVS/UI 선택지를 복원하지 않는다.

## 로그 보강

- 현재 상태 API의 `summon_unlock`에는 게이트 허용, AP 상태·활성,
  안정시간, 차단 사유, 주차, 소환 상태가 이미 있다.
- 스키마 3 시계열 CSV에는 허용·AP 상태·안정시간·차단 사유만 있어
  `a_summon_ap_active`, `a_summon_parked`, `a_summoning`을 추가한다.
- 이 변경은 CAN 송신 조건이나 Mode 3 알고리즘을 바꾸지 않는 수동 진단 보강이다.

## 검증 결과

- 독립 CSV 123열과 통합 로그 121열의 헤더·데이터 열 수가 일치한다.
- 전체 네이티브 테스트 108개가 통과했다.
- HW3 `lilygo_t2can` 펌웨어 빌드가 통과했다.
