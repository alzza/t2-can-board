# 작업 계획

## 목표

- 차량에서 관찰된 A채널 간헐 경고의 실제 원인을 구분할 수 있게 한다.
- 메인·진단 페이지의 통신 상태가 실제 런타임/API 필드와 일치하도록 정리한다.
- A/B 채널 진단 데이터를 CSV로 저장하고 사후 분석할 수 있게 한다.
- 제거된 실험 기능과 연결이 끊긴 UI/API 플래그를 정리한다.
- Web UI를 채널 상태와 기능 상태 중심으로 직관적으로 재배치한다.

## 진행 순서

1. A/B 채널 상태 판정, API, UI 연결을 전수 점검한다.
2. A채널 상태를 `정상/수신 대기/오버런/에러 경고/에러 패시브/BUS-OFF`로 세분화한다.
3. A채널 EFLG 전이와 오버런을 밀리초 이벤트 및 5초 시계열에 기록한다.
4. 자가 진단이 A/B 양쪽과 HW3의 DAS 921/923 경로를 검사하도록 수정한다.
5. 진단 결과 CSV와 전체 시계열 CSV 다운로드를 UI에서 직접 제공한다.
6. 불용 플래그와 숨겨진 실험 UI/API를 제거한다.
7. 메인·진단 화면을 상태 원인과 다음 행동이 먼저 보이도록 재배치한다.
8. Native 테스트, UI 동기화, 보드 빌드, 정적 검사를 실행한다.

## 보류 기준

- A채널 경고 임계값이나 TX Guard 동작시간처럼 차량 송신 동작을 바꾸는 값은 실제 로그 근거 없이 변경하지 않는다.
- Summon 호출 지연을 줄이기 위해 검증된 INO 게이트를 변경하지 않는다.
