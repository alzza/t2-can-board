# Nag Mode 1/2/3 정밀 포팅 컨텍스트 노트

## 최종 구현 결론

- MODE 1/2/3 선택과 원본 상태기계를 HW3 CAN-B에 포팅했다.
- MODE 3만 921/923·297 최근 수신 유효시간과 validity·±5° 게이트를 사용한다.
- 모든 모드는 ±1.80Nm 상한, `sendCheck()` 성공 계수, 전체 프레임 자기 에코 차단을 공통 사용한다.
- Web UI/API/NVS는 MODE 3을 기본으로 사용하고 A~D 프로파일 경로를 폐기했다.

## 차량 안전상 중요한 차이

- 외부 Mode 1/2는 DAS 921과 조향 297을 필터에 요구하지 않고 ID 880과 실제 hands-on만으로 echo한다.
- 외부 Mode 3만 조향 validity 1과 ±5도 조건을 검사한다.
- 현재 프로젝트는 921 또는 923을 DAS 후보로 허용하지만 외부 HW3 원본은 921을 사용한다.
- 이 차이는 송신 허용 범위를 바꾸므로 사용자 확인 전 코드를 수정하지 않는다.

## 최근 수신 유효시간 게이트 설명

- ID 921/923은 AP 상태와 DAS hands-on 상태를 제공하고 ID 297은 조향각을 제공한다.
- ID를 필터에 넣고 값을 읽는 것 자체는 최근 수신 유효시간 게이트가 아니다.
- 최근 수신 유효시간 게이트는 ID 880을 처리하는 순간 `현재 시각 - 마지막 921/923 수신 시각`과 `현재 시각 - 마지막 297 수신 시각`이 각각 1000ms 이하인지 검사하는 송신 허용 조건이다.
- 5월 14일 계열과 직전 수정 전 코드도 마지막 수신 시각은 기록했지만 age를 송신 차단에 사용하지 않았다. 따라서 921/297이 끊겨도 마지막으로 저장된 AP·hands-on·조향 값을 계속 사용할 수 있었다.
- 직전 안전 보완은 유효 DLC의 921/923과 297을 한 번 이상 관측했는지 확인하고, 둘 중 하나라도 미수신이거나 1000ms를 넘으면 ID 880 echo를 보내지 않도록 변경했다.
- 현재 297 처리는 DLC만 확인하며 외부 Mode 3의 validity 비트 1 검사와 조향각 ±5도 제한은 아직 포팅되지 않았다.

## 사용자 확정안

- 기존 `[기본]/A~D` 실험 프로파일을 제거한다.
- Web UI는 `MODE 1`, `MODE 2`, `MODE 3 [기본]` 선택으로 교체한다.
- 새 NVS, NVS 초기화, OTA 안전 초기화는 Nag OFF와 MODE 3 선택을 적용한다.
- Mode 1/2는 검증 원본과 같이 921·297 최근 수신 유효시간 게이트 없이 동작한다.
- Mode 3은 원본 상태기계, 조향 validity 1, 조향각 ±5도 조건을 적용한다.
- 현재 차량 호환성을 위해 Mode 3 DAS 입력은 921과 923을 모두 허용한다.
- ±1.80 Nm 상한, `twai_transmit()` 결과 계수, 자체 echo 차단은 모든 모드에 공통 적용한다.
