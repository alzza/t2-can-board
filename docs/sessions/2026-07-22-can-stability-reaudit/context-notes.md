# 컨텍스트 노트

- 현재 기준은 2026-05-14 복원 커밋과 미커밋 HW3 Summon Unlock 포팅이다.
- 과거에 확인된 주요 오류는 NagTask 우선순위 회귀, 안전하지 않거나 효과가 없던 TX 타이밍 실험, 수동 TWAI 복구 문제, 배선/접지/ACK 문제, 제거된 ID 659의 잘못된 카운터/체크섬이었다.
- 사용자가 어느 채널도 완벽하다고 선언하지 않았으므로 A 채널 진단을 우선한다.
- 구체적 결함이나 사용자 선택 없이는 동작을 변경하지 않는다.

## 점검 결과

- Summon 포팅은 B 채널 Nag 처리기·TWAI 드라이버·태스크 우선순위·복구 경로를 바꾸지 않았다.
- NagTask는 Core 1 우선순위 10이며 A를 먼저 폴링한다. B는 루프당 30프레임 제한, A는 MCP2515 큐를 모두 비운다.
- TSLLC는 CAN 1021 mux 0, Summon은 mux 1이며 A 채널 TX 마스터/가드가 두 경로를 모두 보호한다.
- Web UI/API에는 A/B 상태, MCP EFLG/TEC/REC·가드, TWAI BUS-OFF/RX 누락, Nag 통계, Summon 진단이 남아 있다.
- OTA 조용한 모드는 Update.begin() 전에 A TX·Nag·TSLLC·Summon·실험 송신을 모두 비활성화한다.
- ID 659 제거로 과거의 가장 유력한 애플리케이션 계층 오류 원인을 제거했다.
- INO 포팅으로 MCP2515 고정 필터가 3개에서 280·390·921·1016·1021의 5개로 늘었다. A를 먼저 모두 비우므로 차량에서 B 폴링 지연을 계측해야 하지만 로컬에서는 정량화할 수 없다.
- 새 NVS에서 Summon 활성 및 부팅/감시시간 초과 parked=true는 검증된 INO와 같지만 Summon 깨우기 동작을 위해 의도적으로 fail-open이다.
- 2026-05-14 기준에 남아 있던 레거시 A 채널 실험 송신은 이후 제거했다. 일부 ID 1016 설정은 과거 NVS에서 복원될 수 있었으므로 부팅 삭제 처리를 추가했다.
- 전체 native 명령에는 기준 코드와 맞지 않는 오래된 테스트가 포함되어 있으므로 집중 테스트 결과를 기준으로 삼는다.
