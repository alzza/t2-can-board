## HW3 조건부 Summon Unlock 포팅

- INO 게이트 상태 머신을 A 채널 처리기에 포팅했다.
- CAN 280·390·921·1016·1021을 관찰한다.
- 게이트는 정확히 `Parked || Summoning`이며 CAN 921 AP 상태는 진단 전용이다.
- Summoning은 `ACA && SPR-latched`이고 ACA가 내려가면 SPR을 해제한다.
- CAN 280이 없거나 5000ms 이상 오래되면 CAN 390을 INO 대체 경로로 사용한다.
- CAN 280이 5000ms 이상 조용하면 parked=true로 만든다.
- CAN 1021 mux 1은 Web 활성화와 게이트 개방이 동시에 성립할 때만 주입한다.
- HW3 페이로드는 bit19=0, bit46=1이며 bit47은 유지한다.

## OTA/NVS 안전성 재검토와 Web UI 원본 분리

- 5월 14일 기준과 현재 코드를 비교한 결과 OTA 상태 머신과 업로드 순서는 바뀌지 않았다. 안전 NVS 목록의 기존 EAP 항목이 신규 `summon_unlock=OFF`로 교체됐다.
- OTA 요청은 플래시 쓰기 전에 차량 기능과 A TX를 런타임/NVS OFF로 내리고 B채널 TX 큐를 비운다. 안전 저장 실패 시 업로드를 중단한다.
- 차량의 구 펌웨어는 신규 Summon 키를 모르지만 `a_ch_tx=false`, `nag_killer=false`, `tsllc=false`를 저장하므로 새 펌웨어 첫 부팅의 A채널 실제 주입은 차단된다.
- 다만 CAN 태스크가 `webServerInit()`의 `nag_killer` NVS 로드보다 먼저 시작한다. Nag 관련 빌드 기본값이 ON이므로 부팅 직후 B채널 TX가 잠깐 가능해, OTA 후 차량 오류 문제가 완전히 해결됐다고 볼 수 없다.
- 5월 13일 문서의 “OTA 첫 부팅에서 안전 helper 재호출” 기록은 현재 코드와 확인 가능한 커밋에 구현돼 있지 않았다.
- 권장안은 모든 기능 NVS 선로드와 `ota_pending==1` 안전값 재기록이지만, 사용자 방침에 따라 승인 전 OTA/CAN 동작 수정은 보류했다.
- 새 Web UI를 `web/web_ui.html`에 독립 원본으로 저장하고 `scripts/sync_web_ui.py`로 임베디드 헤더와 동기화하게 했다. mock 서버도 HTML 원본을 직접 읽는다.

## OTA/NVS fail-closed 구현

- 사용자 승인에 따라 차량 영향 NVS 선로드, OTA 첫 부팅 안전값 재기록, NVS 실패 시 CAN 미시작 복구 UI를 모두 구현했다.
- `pending=0~5`, USB 파티션 불일치, fallback 누락, 범위 밖 상태를 `ota_boot_policy.h`로 분리하고 `6~255` 전체 fail-closed 테스트를 추가했다.
- Summon, Nag, TSLLC, A TX/하드웨어, Nag profile, BUS-OFF 설정은 MCP2515/TWAI와 CAN 태스크보다 먼저 원자적으로 선로드한다.
- `pending=1`은 현재 펌웨어가 아는 안전 키를 OFF/stock으로 다시 저장하므로 구 펌웨어에 없던 `summon_unlock`도 첫 부팅 전에 OFF가 된다.
- OTA 업로드·자동/수동 rollback·복구 진입은 안전값 저장과 B TX queue clear를 확인한다. 오류면 재부팅하지 않고 복구 UI로 전환한다.
- OTA metadata commit 실패는 현재 실행 파티션을 boot 대상으로 복원한다. NVS erase 복구와 Web NVS reset도 다음 부팅을 OFF/stock으로 고정한다.
- 복구 UI와 `/api/status`에 `can_boot_block_reason`을 추가했다.
- 검증은 정책 7/7, 집중 15/15, 전체 native 91/91, Nag 43/43, HW3 빌드, Web UI 동기화, printf 검사, `git diff --check`가 통과했다.
- 최종 HW3 빌드는 RAM 106776바이트(32.6%), Flash 981881바이트(49.9%)이며 바이너리 크기는 982240바이트, SHA-256은 `a7f32ec0f919092eab2e527201fd63b25bc0a7095b0821376e1bea4abe16cac0`이다.
- 실차에서는 첫 부팅 후 기능이 모두 OFF인 상태로 A/B 수신과 BUS-OFF를 확인하고 OTA 확인을 누른 뒤 기능을 하나씩 재활성화해야 한다.
