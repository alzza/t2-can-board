## 2026-05-09 16:52 KST - Nag Killer Mode B 중단 원인 로그 분석

사용자 요청:
- `canmod_20260509_165201.txt` 기준으로 Nag Killer가 왜 제대로 동작하지 못했고 어떤 이유로 중단됐는지 판정한다.

확인:
- 마지막 10분 시계열 120개 샘플은 모두 `nagMode=1`, 즉 Mode B 스마트 상태머신 상태였다.
- B채널은 `BUS-OFF=0`, `TEC=0`, `REC=0`, `TxFail=0`, `EchoDrop=0`, `RxMissed=0`으로 통신 오류 때문에 중단된 흔적이 없었다.
- 16:49:16 이후 마지막 32개 샘플 약 160초 동안 `d880=16005`, `dSkipAP=16005`, `dEcho=0`, `dModeBInject=0`이 완전히 일치했다.
- 최종 중단 원인은 태스크/드라이버 장애가 아니라 Mode B의 AP gate였다. `DAS_autopilotState`가 1 또는 2로 내려가면서 현재 구현의 허용 범위 `3..6` 밖이 되어 모든 880 프레임이 `AP_BLOCK` 처리됐다.
- `modeBFirstEchoDelayMs` 이벤트는 추적변수가 효과가 있음을 보여준다. State 2 첫 echo는 대부분 2000/2001ms, strong state 첫 echo는 1000ms, state 1 grace echo는 1ms로 기록됐다.

판정:
- 중단 원인: Mode B AP state gate 차단.
- 스마트 토크 타이밍: State 2의 2초 지연은 실차 경고 대응용으로는 늦을 가능성이 높다. 우선 `kNagModeBState2DelayMs`를 2000ms에서 500~800ms 범위로 줄이고, strong delay는 1000ms에서 300~500ms 범위로 줄이는 후보가 합리적이다.
- 스텔스 Mode A 직접 로그는 마지막 10분에 없어서 현재 첨부만으로는 별도 판정 불가. 다만 `echoCount`와 `modeBInjectCount` 차이로 이전 구간에 Mode A 또는 비-ModeB echo 이력이 있었던 것으로 보인다.

다음 액션:
