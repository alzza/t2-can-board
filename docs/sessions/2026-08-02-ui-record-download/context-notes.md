# 컨텍스트 노트

## 사용자 확정 사항

- 신호 관찰기는 더 이상 사용하지 않으므로 완전히 제거한다.
- Web UI는 제안 A안인 `상태 / 제어 / 진단 / 기록 / OTA`로 구성한다.
- CSV 저장과 통합 로그 다운로드의 먹통처럼 보이는 현상을 함께 개선한다.
- 차량은 HW3이며 기존 CAN 주입 로직은 변경하지 않는다.

## 원인 분석

- `TsSample` 한 개는 332바이트이고 최대 240개를 통합 로그 생성 전에 복사했다.
- 이 스냅샷은 약 79,680바이트를 한 번에 할당해, 재부팅 직후 약 94KB 수준의 여유 힙에서 HTTP/TCP 처리 공간을 지나치게 줄일 수 있었다.
- 브라우저는 통합 로그 저장 후 상태 갱신을 무조건 180초 중단해 실제 다운로드가 끝나도 UI가 먹통처럼 보였다.
- 실차 CSV의 헤더·데이터 열 수는 일치했으므로 이번 문제의 주원인은 CSV 인자 수 불일치가 아니다.

## 적용 원칙

- 통합 로그는 `timeseriesCopyAt()`로 한 행씩 짧게 복사한 뒤 즉시 전송한다.
- 다운로드 중 UI 갱신 중단은 통합 로그 15초, 개별 CSV 10초로 제한하고 기록 화면에 상태를 표시한다.
- 과거 세션 문서는 변경 이력 보존을 위해 삭제하지 않는다.
