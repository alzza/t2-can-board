# 2026-08-02 작업 대화 기록

## 요청

- 2026-08-01 실차 로그에서 확인된 불안정 요소를 하드웨어 교체가 아닌 소프트웨어로 줄일 방안을 구상했다.
- 사용자는 제안한 1단계 A채널 수신 안정화 작업을 진행하도록 승인했다.

## 합의

- 검증된 HW3 차량 제어 비트와 조건부 주입 로직은 변경하지 않는다.
- 먼저 수신 버퍼 편중, 폴링 공백, CAN 태스크의 진단 작업 부하를 줄인다.
- TX Guard 정책 변경은 이번 펌웨어의 실차 로그를 검증한 다음 2단계로 판단한다.

## 반영 내용

- MCP2515 필터 배치를 RXB0/RXB1 부하 분산 방향으로 조정했다.
- A채널 하드웨어 수신을 32프레임 RAM 큐로 먼저 회수하도록 변경했다.
- B채널 처리 중 A채널 재서비스 간격을 프레임 한 개로 줄였다.
- 고정 1ms CAN 태스크 대기를 제거하고 짧은 microsecond 대기와 주기적 RTOS 양보를 적용했다.
- 5초 상태 로그 생성을 Core 0 전용 태스크로 옮겼다.
- 원인 검증용 RXB별 수신·오버런, RAM 큐, 세분화된 루프 공백, 오버런 단계를 API·Web UI·CSV에 추가했다.

## 실차 후속 확인

- 새 로그에서는 누적값 자체보다 시험 구간 동안의 증가량을 비교한다.
- RX 큐 드롭은 0이어야 하며 RX0/RX1 오버런 증가율, 1ms/2ms 초과 공백, BUS-OFF·TEC·REC·MERRF를 함께 본다.
- 제어 기능이 그대로 유지됐는지 ECE R79, Summon, TSLLC, Nag Killer 상태와 실제 송신 증분도 함께 저장한다.
