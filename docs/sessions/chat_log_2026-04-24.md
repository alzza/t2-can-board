## 대화 흐름 요약

### 1. WDT/무한재부팅 위험성 분석

**질문:** "NagTask 우선순위를 10으로 높이면 WDT Panic이 생기지 않나?"

**분석 결과: 안전 확인**

| 안전 장치 | 위치 | 동작 |
|-----------|------|------|
| `vTaskDelay(pdMS_TO_TICKS(1))` | `nagKillerTask` 루프 끝 | 매 반복 IDLE yield |
| `rxLimit = 30` | 수신 루프 | 버스 폭주 시 최대 30프레임 후 강제 break |
| WiFi 스택 prio ~23 | Core 0 | NagTask(10)를 주기적으로 선점 → CPU 독점 불가 |

**과거 WDT Panic 원인:** `rxLimit` 없이 버스 폭주 → vTaskDelay 미도달 → WDT kick 불가.
현재는 `rxLimit=30` 으로 방지됨.

### 2. NagKiller 실패 원인 4가지 분석 (git 히스토리 추적)

`git log --oneline`으로 커밋 히스토리를 역추적, 동작 성공 기준점(f494089) 대비 비교.

#### 원인 1: `NagHandler_Original`에서 `delayMicroseconds(100)` 누락

**발생 경위:** NagHandler → Original + Stealth 이중화 작업 중 신규 작성된 Original에서 누락됨.

**물리적 메커니즘:**
```
Tesla 880 프레임 도착 → 수신 완료 → 버스는 아직 idle 전
     └── 즉시 echo 송신 → 반사파 충돌 → TX 에러 누적
```
500kbps 기준 1bit = 2μs, `delayMicroseconds(100)` = 약 2.5 비트 길이의 inter-frame space.

**증상:** TX 에러 카운터 급증 → error-passive(128) → BUS-OFF 반복.

**수정:** `include/handlers.h` line 304 — `driver.send(echo)` 직전에 추가.

---

#### 원인 2: TX 백오프 파라미터 역효과

**기존 설정:**
```cpp
if (twSt.tx_error_counter >= 128) {   // error-passive 진입점
    driverB->setTxBackoff(200);        // 200ms 에코 중단
}
```

**문제:** 100Hz 버스에서 200ms = 에코 20프레임 완전 공백 → Tesla DAS가 나그 재발동.

**수정 (`src/main.cpp` line 713-714):**
```cpp
if (twSt.tx_error_counter >= 200) {   // 실제 위험 구간
    driverB->setTxBackoff(15);         // 15ms = 약 1.5프레임만 건너뜀
}
```

**실차 결과:** TX 에러 피크 248 → 168, BUS-OFF 5 → 2 개선 확인.

---

#### 원인 3: NagTask 우선순위 하락 (10 → 4)

**Core 0 우선순위 구조:**
```
WiFi 스택:    prio ~23
NagTask:      prio  4  ← (문제) WebServer(5)에 선점당함
WebServer:    prio  5
EspNowTx:     prio  1
```

**문제:** 880 프레임 수신 후 echo 발사 직전 WebServer가 CPU 탈취 → echo 지연 → 나그 재발동.

**수정 (`src/main.cpp` line 1026):** `xTaskCreatePinnedToCore(..., 4, ...)` → `(..., 10, ...)`.

---

#### 원인 4: `twai_initiate_recovery()` 수동 호출로 RECOVERING 영구 고착

**기존 코드:** BUS-OFF 감지 시 `twai_initiate_recovery()` 수동 호출.

**문제:** GND 미접지 환경에서 `TWAI_STATE_RECOVERING` 영구 고착.

**수정:** 수동 호출 제거, TWAI 하드웨어 자동 복구(128 consecutive recessive bits) 위임.
커밋 34f87f0, 3d5fe16에서 이미 제거됨 — 이번 세션에서 미제거 상태인지 재확인.
